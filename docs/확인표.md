# 확인표와 검증 기록

## 로컬에서 확인 완료한 것

- [x] 한국 자정 경계, 날짜 계산, 연체 판정, 중복/날짜/빈 입력 검사, 검색/이력/HTML 이스케이프 단위 테스트 10개 통과.
- [x] `npm.cmd run build`로 배포용 파일 생성 성공.
- [x] Edge 실제 브라우저에서 로그인 전 데이터 숨김, 체험 대여 4건/연체/오늘 반납 구분 확인.
- [x] 등록, 중복 거부, 반납 취소/확인, 완료 탭의 오늘 날짜, 검색, 이력, HTML 삽입 차단 확인.
- [x] 등록 후 새로 불러오기·반납 버튼 활성 상태 확인.
- [x] 390px 모바일 화면에서 페이지 가로 넘침 없음, 표는 가로 스크롤 가능. 모달 Escape 닫기 확인.
- [x] 브라우저 JavaScript 오류 없음.
- [x] PostgreSQL 18.6(PGlite 0.5.10)에서 `setup.sql` 첫 실행/재실행 및 실제 기록 보존 확인.
- [x] PostgreSQL에서 `verify.sql`의 비로그인 접근 차단, 인증 사용자 조회/등록/반납, 컬럼 권한, 날짜/중복/변경 차단과 롤백 확인.
- [x] SQL 검증의 계정 0명 안내, 1명/2명 계정 조건 확인.

SQL 로컬 검사는 `auth.uid()`, `auth.users`, 역할을 시뮬레이션했습니다. 실제 Supabase Auth 서버가 발급하는 JWT와 PostgREST HTTP 요청 통합은 포함하지 않았습니다. Supabase 프로젝트 버전이 로컬 엔진 버전과 다를 수 있으므로 아래 실제 연결 확인이 남습니다.

스크린샷과 상세 로그는 프로젝트 내부 `artifacts/`, `.cache/sql-verify/`에 있습니다. 이 임시 결과물은 Git에서 제외합니다.

## 본인 서비스 연결 후 확인할 것

- [ ] GitHub 저장소에 코드가 올라갔다.
- [ ] Vercel 빌드가 Ready이고 대표 주소로 사이트가 열린다.
- [ ] Supabase 전용 프로젝트에 setup.sql을 실행했다.
- [ ] Allow new users to sign up과 익명 로그인을 껐다. Email 로그인은 켜 두었다.
- [ ] Supabase Auth에 구성원 계정을 직접 만들었다.
- [ ] Vercel 환경변수 2개를 입력한 후 다시 배포했다.
- [ ] 실제 계정으로 로그인/새로고침/로그아웃이 된다.
- [ ] 비로그인 시 실제 장부를 볼 수 없다.
- [ ] 계정 A가 등록한 기록을 계정 B가 보고 반납할 수 있다.
- [ ] 반납일이 한국 오늘 날짜이며, 반납 완료 탭에서 보인다.
- [ ] 같은 물품 동시 등록 시 1건만 저장된다.
- [ ] 반납한 물품을 다시 빌려도 과거 이력이 유지된다.
- [ ] 어제 예정인 대여는 빨간색, 오늘 예정인 대여는 오늘 반납으로 보인다.
- [ ] 비밀키와 .env.local이 GitHub에 올라가지 않았다.
- [ ] Supabase SQL Editor에서 verify.sql 실행 후 검증이 통과했다.

실제 외부 계정 연결 전에는 위 항목을 완료 처리하지 않습니다.
