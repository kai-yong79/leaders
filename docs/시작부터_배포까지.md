# 주인님을 위한 시작부터 배포까지

주인님의 저장소는 [kai-yong79/leaders](https://github.com/kai-yong79/leaders)로 정해졌습니다. 새 저장소 생성은 완료된 상태이므로 1단계의 업로드 확인부터 진행하면 됩니다. 아래 새 저장소 생성 절차는 처음부터 다시 만드는 경우에 참고하세요.

이 안내는 **GitHub → Vercel → Supabase → 실제 로그인 확인** 순서입니다. 코드는 이미 `C:\project\leader4` 안에 준비되어 있습니다. 다른 폴더에 파일을 만들 필요가 없습니다.

## 1. GitHub에 코드 보관함 만들기

1. [GitHub](https://github.com)에 로그인합니다. 계정이 없으면 Sign up으로 만듭니다.
2. 오른쪽 위 `+` → **New repository**를 누릅니다.
3. Repository name에 `leaders`를 입력합니다.
4. 공개 범위는 **Private**를 선택합니다.
5. README, .gitignore, license 자동 생성은 선택하지 않습니다. 이미 로컬에 파일이 있습니다.
6. **Create repository**를 누릅니다.
7. 표시된 주소 `https://github.com/kai-yong79/leaders.git`를 복사합니다.

VS Code에서 `C:\project\leader4`를 연 뒤 **터미널 → 새 터미널**에서 아래를 실행합니다.

```powershell
cd C:\project\leader4
git status
```

이 프로젝트를 만들면서 로컬 Git 초기화와 첫 커밋까지 완료했다면 아래 두 줄만 실행합니다. **내아이디**는 실제 GitHub 아이디로 바꾸세요.

```powershell
git remote add origin https://github.com/kai-yong79/leaders.git
git push -u origin main
```

브라우저의 GitHub 로그인/권한 확인이 뜨면 본인 계정으로 진행합니다. GitHub 저장소를 새로고침했을 때 `README.md`, `src`, `supabase`가 보이면 성공입니다.

아직 Git 저장소가 없는 복사본이라면 다음 명령을 먼저 실행합니다.

```powershell
git init -b main
git add .
git commit -m "공용물품 대여 장부 초기 구현"
```

`Author identity unknown` 메시지가 나오면 다음 두 줄에서 이름과 이메일을 본인 정보로 바꾸고 다시 커밋합니다. `--global` 없이 이 프로젝트에만 설정합니다.

```powershell
git config user.name "내 GitHub 이름"
git config user.email "내 GitHub 이메일"
```

`remote origin already exists`가 나오면 `git remote -v`로 주소를 확인하세요. 기존 주소를 임의로 바꾸지 말고 올릴 저장소가 맞는지 확인합니다.

`.env.local`, `node_modules`, `.cache`, `dist`, `artifacts`는 제외됩니다. 환경파일을 웹 업로드로 따로 올리지 마세요. 다른 컴퓨터에 필요한 패키지 목록과 고정 버전은 `package.json`, `package-lock.json`으로 전달됩니다.

GitHub 공식 안내: [기존 코드 올리기](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github).

## 2. Vercel에서 인터넷 주소 만들기

1. [Vercel](https://vercel.com)에 접속하고 **Continue with GitHub**로 로그인합니다.
2. **Add New → Project**를 선택합니다.
3. `leaders` 저장소 옆 **Import**를 누릅니다.
4. 안 보이면 **Configure GitHub App**에서 이 저장소 접근을 허용합니다.
5. 설정을 확인합니다.

| 항목 | 값 |
| --- | --- |
| Framework Preset | Vite |
| Root Directory | 기본값 `./` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | 기본값 |

6. **Deploy**를 누릅니다.
7. 배포 상태가 Ready가 되면 생성된 웹사이트를 엽니다.
8. 이 단계에서는 **연결 준비 중**이 정상입니다. **체험 장부 열어보기**로 화면을 확인합니다.
9. Vercel의 프로젝트 **Settings → Domains**에 표시된 실제 대표 주소를 복사해 둡니다. 저장소 이름과 반드시 같지는 않습니다.

환경변수를 이미 준비했다면 처음 배포할 때 바로 입력해도 됩니다. 아직 Supabase를 만들지 않았다면 다음 단계 후 입력합니다.

이 앱은 Vite 앱이므로 수업의 빌드 없는 HTML 예시처럼 `Other`를 고르지 않습니다. [Vercel Vite 공식 안내](https://vercel.com/docs/frameworks/frontend/vite).

## 3. Supabase에 로그인과 DB 만들기

1. [Supabase](https://supabase.com)에 로그인합니다.
2. **New project**를 누르고 조직을 선택하거나 만듭니다.
3. 이 부서 장부 전용 프로젝트 이름을 `leaders`로 정합니다. 이 프로젝트에 있는 모든 로그인 계정은 같은 장부를 볼 수 있습니다.
4. DB 비밀번호는 본인 비밀번호 관리 도구에 보관합니다. 앱 파일이나 채팅에 적을 필요가 없습니다.
5. Region은 제공되는 목록에서 서울 또는 가까운 지역을 선택합니다.
6. 생성이 끝날 때까지 기다립니다.

### 3-1. 테이블·접근 정책 만들기

1. 왼쪽 **SQL Editor → New query**를 엽니다.
2. 프로젝트의 `supabase/setup.sql` 파일 전체를 복사하여 붙여넣습니다.
3. **Run**을 누릅니다. 테이블 생성·정책 갱신 경고가 나오면 실행할 SQL 내용이 맞는지 보고 진행합니다.
4. **Table Editor**에서 `rentals` 테이블이 있는지 확인합니다. 처음에는 0건이 정상입니다. 체험용 가상 기록은 DB에 넣지 않습니다.
5. 정책은 아래 SQL로 확인할 수 있습니다. 인증 사용자용 SELECT, INSERT, UPDATE 총 3개입니다.

```sql
select policyname, cmd, roles
from pg_policies
where schemaname = 'public' and tablename = 'rentals'
order by policyname;
```

### 3-2. 구성원 로그인 계정 만들기

1. **Authentication → Sign In / Providers**의 회원가입 설정에서 **Allow new users to sign up**을 끕니다.
2. **Allow anonymous sign-ins**도 꺼 둡니다. **Email 로그인 자체는 켜 둡니다.**
3. 이 앱은 회원가입 버튼을 제공하지 않습니다. 계정은 관리자만 발급합니다.
4. **Authentication → Users → Add user → Create new user**를 선택합니다.
5. 구성원의 이메일과 비밀번호를 입력합니다. **Auto Confirm User** 옵션이 있으면 켜서 해당 관리 계정을 확인 완료 상태로 생성합니다.
6. 테스트용 본인 계정부터 한 개 만들고, 필요하면 다른 구성원 계정을 추가합니다. 사용자마다 서로 다른 계정을 쓰세요.

앱에서 비밀번호 찾기를 별도로 제공하지 않습니다. 잊어버리면 운영 관리자가 Supabase의 사용자 관리에서 비밀번호를 재설정해야 합니다. **Send invitation**은 이메일 링크 처리 화면이 별도로 필요하므로 현재 안내에서는 직접 계정 생성을 사용합니다.

공식 설정 설명: [회원가입 허용과 이메일 확인](https://supabase.com/docs/guides/auth/general-configuration).

### 3-3. 앱 연결용 주소와 공개용 키 가져오기

프로젝트 **Connect** 창 또는 **Settings → API Keys / Data API**에서 다음 두 값을 찾습니다.

- **Project URL**: `https://...supabase.co` 형태
- **Publishable key**: `sb_publishable_...` 형태

Supabase 프로젝트에 따라 `anon` 구형 공개키도 보일 수 있습니다. 새 연결은 Publishable key를 쓰세요. **Secret / service_role / Database password**는 앱에 넣는 값이 아닙니다.

## 4. Vercel에 연결 값 넣고 재배포

1. Vercel에서 해당 프로젝트의 **Settings → Environment Variables**로 이동합니다.
2. 변수 2개를 각각 추가합니다. 이름은 정확히 일치해야 합니다.

| Name | Value |
| --- | --- |
| `VITE_SUPABASE_URL` | 복사한 Project URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | 복사한 Publishable key |

3. 연결할 환경은 **Production**을 선택합니다. Preview에서도 실제 장부로 테스트할 경우 Preview도 선택합니다. Preview도 같은 DB를 사용하면 테스트 등록이 실제 기록에 남습니다.
4. 값을 입력할 때 앞뒤 따옴표와 공백은 넣지 않습니다.
5. **Deployments → 최신 배포의 ⋯ → Redeploy**를 누릅니다.
6. Ready 이후 대표 주소를 새로고침합니다. 연결 안내가 사라지고 이메일/비밀번호 로그인이 활성화되면 설정을 읽은 것입니다.
7. Supabase에서 만든 계정으로 로그인합니다. 처음 장부는 비어 있습니다.

Vite는 빌드할 때 환경변수를 읽으므로 저장만으로 기존 배포가 바뀌지 않습니다. [Vercel 환경변수 공식 안내](https://vercel.com/kb/guide/how-to-add-vercel-environment-variables).

## 5. 내 컴퓨터에서도 같은 DB 사용하기

터미널에서 다음을 실행합니다.

```powershell
cd C:\project\leader4
Copy-Item .env.example .env.local
```

이미 `.env.local`을 채웠다면 복사 명령으로 덮어쓰지 마세요. VS Code에서 `.env.local`을 열고 같은 주소/공개키를 입력합니다.

```dotenv
VITE_SUPABASE_URL=https://내프로젝트주소.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_내공개용키
```

저장 후 기존 서버에서 `Ctrl+C`, 다음을 실행합니다.

```powershell
npm.cmd run dev
```

같은 Supabase 프로젝트에 연결했다면 내 컴퓨터와 Vercel 사이트에서 같은 기록을 봅니다.

## 6. 실제 장부 확인하기

1. 대표 주소에서 계정 A로 로그인합니다.
2. 물품 `테스트 노트북 01`, 대여자 `테스트 담당자`, 오늘 날짜와 미래 예정일로 등록합니다.
3. 새로고침하고 로그인 유지와 기록 보존을 확인합니다.
4. 시크릿 창에서 같은 주소를 엽니다. 로그인 전에는 장부가 보이지 않아야 합니다.
5. 계정 B로 로그인하고 **새로 불러오기**를 눌러 A가 등록한 기록을 확인합니다.
6. B가 **반납 → 반납 확인**을 누릅니다.
7. **반납 완료** 탭에서 오늘 반납일을 확인합니다.
8. 물품명을 눌러 이력을 확인합니다.
9. 같은 물품을 다시 빌리면 새 기록이 생기고 이전 반납 기록은 남아 있어야 합니다.
10. 연체 확인은 대여일을 이틀 전, 예정일을 어제로 등록하면 됩니다. 오늘 예정인 물품은 연체가 아닙니다.

추가 DB 검사: 계정 1개 이상 만든 뒤 `supabase/verify.sql` 전체를 SQL Editor에서 실행합니다. 테스트 기록은 마지막 `ROLLBACK`으로 취소됩니다. 오류로 실행이 중단되면 같은 편집기에서 `ROLLBACK;`을 실행하세요. 이 검사는 실제 이메일 로그인/인터넷 연결 검사를 대신하지 않습니다.

## 7. 앞으로 수정해서 다시 올리는 방법

수정·저장한 다음 터미널에서 실행합니다.

```powershell
cd C:\project\leader4
npm.cmd test
npm.cmd run build
git status
git add .
git commit -m "바뀐 내용을 한 줄로 설명"
git push
```

main으로 푸시하면 연결된 Vercel 프로젝트가 자동으로 다시 배포합니다. 환경변수만 바꿨다면 코드 푸시 없이 Redeploy할 수 있습니다.

## 막힐 때

| 화면/오류 | 확인할 내용 |
| --- | --- |
| npm 명령을 찾을 수 없음 | Node.js LTS 설치 후 VS Code를 완전히 닫았다 다시 열기 |
| PowerShell 스크립트 실행 거부 | 이 문서처럼 `npm.cmd`로 실행 |
| 연결 준비 중 | 로컬 `.env.local` 또는 Vercel 변수 이름/값 확인 후 서버 재시작/재배포 |
| 로그인 실패 | Supabase 프로젝트와 계정 이메일/비밀번호, 사용자 확인 상태 확인 |
| 테이블이 없음 | `setup.sql` 전체 실행 여부 확인 |
| 접근 권한 없음 | 로그인 상태와 RLS·컬럼 권한 확인. SQL 전체를 다시 실행 |
| 이미 대여 중 | 기존 대여 반납 후 등록 또는 실제 물품 번호 확인 |
| 다른 컴퓨터의 변경이 안 보임 | 체험 모드인지 확인, 같은 Supabase 주소인지 확인, 새로 불러오기 |
| 사이트가 Vercel 로그인 요구 | 대표 도메인인지 확인하고 Vercel Deployment Protection 설정 확인 |
| 주소는 열리는데 DB 연결 실패 | Supabase 대시보드의 프로젝트 작동 상태·인터넷 연결 확인 |
| push 거부 | 원격 저장소에 다른 기록이 있는지 확인. 강제 push 없이 오류 메시지를 그대로 전달 |

도움을 요청할 때 **하던 일, 기대한 결과, 실제 결과, 오류 문구, 최근 바꾼 것** 다섯 가지를 알려 주세요. 비밀번호·Secret 키는 보내지 마세요.
